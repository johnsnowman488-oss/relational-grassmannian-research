# bAbI Tasks 3 and 5 — HLA/HLB Learning Protocol v1.1

**Protocol ID:** HLG-BABI-T3-T5-LEARNING-v1.1  
**Status:** FROZEN — 2026-11-26, subject to the independent-source G0.5 verification in the byte freezer  
**Supersedes:** v1.0, before any learning campaign or candidate selection  
**Implementation:** stacked on H1 learning runtime PR #50  
**Scope:** structured-event learning and retrieval; natural-language parsing is excluded.

## 1. Why v1.1 replaces v1.0

During preprocessing debugging, the official `en-10k` test answers were inadvertently inspected to validate the deterministic source-template adapter. No model was trained, no candidate was selected and no campaign metric was computed from those labels. Nevertheless, the original confirmatory-sealing condition was no longer satisfied.

Therefore **both `en-10k` test files are quarantined**. They may be retained as preprocessing/debugging provenance, but must not be used for model fitting, candidate selection, validation or confirmatory metrics. Protocol v1.1 replaces them with the separate official `en` test files from the same v1.2 archive. The freezer must establish exact zero overlap between each `en` confirmatory story and both the corresponding `en-10k` training-source and quarantined test stories, using normalized story text with answer/support columns excluded. If overlap is nonzero, G0.5 fails and no campaign may start.

## 2. Research questions

**Task 3 — Three Supporting Facts:** reconstruct an object's location immediately before the semantically identified movement to a queried destination, integrating pickup, movement and drop/discard events while preserving the exact supporting event chain.

**Task 5 — Three Argument Relations:** represent each GIVE as one n-ary event `GIVE(giver, object, recipient)`, answer role-conditioned questions, and prevent participant roles from being assembled across different event identities.

The campaign reports task-answer quality, learned event prediction, evidence integrity and operational behaviour separately.

## 3. Data identity and partitions

Use the pinned official bAbI v1.2 archive, English. Training and validation use the `en-10k` training source:
- **Fit:** 1,800 complete stories per task.
- **Validation:** 200 complete, disjoint stories per task, derived deterministically from the 2,000-story source by the frozen SHA-256 story-block ranking.

Confirmatory data use the official `en` test files:
- Task 3: `tasks_1-20_v1-2/en/qa3_three-supporting-facts_test.txt`.
- Task 5: `tasks_1-20_v1-2/en/qa5_three-arg-relations_test.txt`.

Their exact story counts, file hashes and zero-overlap audit are generated by the source freezer and recorded in the manifest. Confirmatory labels are not read by the annotation compiler, not included in model inputs, and not scored until G4 after candidate fingerprints and validation decisions are frozen.

The previous `en-10k` test files remain under explicit `*_test_debug_only.txt` names and are excluded from all campaign metrics.

## 4. Structured annotation and leakage controls

A deterministic, narrow source-template compiler converts the controlled benchmark sentences into typed events. This is not a general natural-language parser and no parser performance claim is made.

Every event/query carries a story-scoped ID and exact source-line provenance. The model input bundle excludes gold answers and official supporting-line IDs. Fit/validation labels are stored separately for post-prediction scoring and fit-only task-outcome calibration. Confirmatory annotation emits **inputs only**; it does not emit a label file.

### Task 3

Recognise MOVE, PICK_UP and DROP events, including benchmark surface variants such as `got ... there`, `took`, `picked up`, `left` and `discarded`. The query compiler identifies the target MOVE from the question destination and story timeline: it must be a MOVE by the actor currently holding the queried object. The answer is the object's location immediately before that exact event. Gold supporting-line IDs are not used to choose the target event.

### Task 5

Recognise GIVE events in active and passive forms, plus MOVE/PICK_UP/DROP distractors that occur in the same stories. A query is represented as bound roles plus a distinct answer role. All bound roles must match within one GIVE event. The answer role is never included among the bound roles.

## 5. Matched HLA/HLB execution

- Same structured event/query inputs, feature encoding, SOE configuration, native kernels, cross-level gains, `dt`, prediction cutoffs and horizons.
- Ten paired seeds: `953000–953009`. The same SHA-256-ranked fit-story permutation is used for HLA and HLB within each seed; within-story source order is preserved.
- One online pass through the 1,800 fit stories. Issue eligible forecasts from pre-event state, ingest the event, score only newly observable targets, then apply permitted learning updates.
- Validation and confirmatory partitions do not update any learner.
- Fresh trusted state for every architecture/task/seed. No state carries across seeds or task IDs.
- SOE decay/configuration, native kernels, `dt`, feature dimensions and cross-level gains remain frozen.
- HLA receives the current story's complete caller-supplied evidence window. HLB uses its canonical store with story-scoped retrieval. Cross-story evidence access is forbidden.

## 6. Learning conditions

Run the six matched conditions:
1. `full_learning`
2. `no_temporal`
3. `no_relational`
4. `no_abstraction`
5. `no_task`
6. `no_learning`

All conditions receive identical fit examples and update opportunities. A disabled channel suppresses only its designated learner updates. The no-learning condition still predicts and scores but makes zero online updates.

The deterministic structured reference solver and direct retrieval baseline are reported separately. They are not labelled learned HLA/HLB performance.

## 7. Metrics

**Task 3:** exact answer accuracy, support-event recall, temporal-order validity, abstention and coverage.

**Task 5:** exact answer accuracy, same-event role-binding accuracy, witness recall, cross-event role-mixup rate, abstention and coverage.

**Learning:** L0 feature forecast error by horizon; L1 event-type and complete role-binding exact accuracy; L2 context-transition accuracy where a defined target exists; per-channel loss, calibration, coverage and update counts.

**Integrity:** false exact-witness rate, missing-witness abstention, provenance verification, cross-story contamination, late-observation leakage and prediction/evidence cutoff violations.

**Operations:** throughput, wall time, HLB store occupancy, prediction/eligibility journal sizes, checkpoint size and restore time. This is not the separate architecture cost/workload sweep.

## 8. Candidate selection and confirmatory lock

Select candidates on validation only: exact-answer accuracy, then mandatory evidence-integrity gates, L1 event/role forecast accuracy, lower abstention, and stable candidate ID as final tie-break.

Any false exact witness, cross-story contamination, leakage violation, role-mixup on fully specified exact-match queries, or provenance-integrity failure rejects a candidate regardless of accuracy.

Before G4, freeze candidate fingerprints, implementation commit, protocol/criteria fingerprints, source and annotation manifests, validation metrics and acceptance decisions. Then access the official `en` test labels once. No test-driven retuning or candidate promotion is permitted.

## 9. Statistical reporting

Report per-seed scores, pooled micro/macro scores, exact denominators, and paired story-level bootstrap 95% intervals. Bootstrap units are stories clustered within seed. Repeated seeds over the same stories are not independent confirmatory samples.

## 10. Execution gates

- **G0:** verify pinned archive, en-10k fit/validation files and independent en test files.
- **G0.5:** verify zero normalized story-block overlap of en confirmatory versus en-10k training and quarantined test sources.
- **G1:** source-indexed structured input annotation, fit/validation oracle audit and annotation-manifest freeze; confirmatory inputs only, no labels.
- **G2:** full current-head CI, H1 adapter/evidence acceptance and compiled-native smoke.
- **G3:** fit/validation learning, six ablations, candidate selection/rejection/promotion and candidate freeze.
- **G4:** one-time independent en confirmatory campaign.
- **G5:** artifacts, hashes, evidence ledger and claim-boundary review.

G0.5, G1 and G2 are hard gates before learning. G3 is a hard gate before confirmatory labels are accessed.

## 11. Claim boundaries

The experiment measures structured-event learning and retrieval, not natural-language parsing, unrestricted semantic understanding, open-world reasoning or general intelligence. It cannot establish universal HLA/HLB superiority. H0 SOE/native stability evidence does not automatically extend to new learning rules or operating envelopes.
