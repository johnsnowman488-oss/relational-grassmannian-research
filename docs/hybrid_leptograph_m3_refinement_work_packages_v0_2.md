# HLG-M3 v0.2 concurrent refinement work-package briefs

**Campaign:** HLG-M3-FINAL-REFINEMENT-v0.2  
**Execution:** one workflow; six package jobs concurrent; full tests concurrent; one terminal evidence aggregate.

## M3-A — Context routing
Verify transported-metric context scores and that context-dependent features are admitted only after ACCEPT. Keep unresolved NOVEL and ABSTAIN distinct. A newly created slot becomes eligible on a later accepted observation, not retroactively on the novelty-creation event.

## M3-B — Joint learning and identifiability
Exercise the actual heterogeneous predictor. Report per-source conditional rank and condition after projection on all other feature blocks. Include a collinear-source counterexample: ridge may stabilise a solve but must not mark the source identifiable.

## M3-C — Effective activation
Use activation state as a real prediction gate. Compare active and dormant effective predictions while proving the stored operator remains nonzero. The shadow prediction is for usefulness diagnostics only and must not be confused with the effective learner output.

## M3-D — Candidate revision
Connect residual alarm, candidate fitting, separate sequential validation and accepted-operator promotion/rejection. Report candidate training/validation counts, both losses, identifiability, decision and incumbent change. No alarm or rejected candidate remains a valid research finding.

## M3-E — C0-C4 resources
Report persistent state bytes, parameter count/bytes, precision, update operations and query operations. Current C3/C4 settings are not matched. Preserve this as an explicit resource/Pareto limitation.

## M3-I — Integrated sequential probe
Run context decision, source shadow predictor, effective route gates, prequential scoring/update, evidence/activation, residual detector, candidate training/validation and C3/C4 counters in one sequential stream. Keep generator schedule labels outside learner functions.

## Common evidence format

Each job writes one JSON artifact with campaign ID, package ID, execution status, measurements, scientific checks, interpretation and limitations. Execution status describes evidence production only. The aggregate reports individual scientific checks without collapsing them into a single M3-success Boolean.
