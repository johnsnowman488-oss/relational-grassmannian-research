# LG-01A — Transient Mode Behaviour

**Protocol version:** LG-01A-v0.1  
**Status:** Frozen design specification; implementation and runs not yet started  
**Research hypothesis:** LGDH — Lepto-Graph Development Hypothesis  
**Opened:** 2026-11-14

## 1. Research question

Can a fast, multidimensional memory mode remain operational under a continuing bounded flow of information even though the contribution from any particular earlier input decays rapidly?

LG-01A tests the transient-refresh operating premise only. It does **not** test graph formation, destination selection, slow-memory registration, adaptive routing, neurogenesis, synaptogenesis or reasoning.

## 2. Hypothesis and null

### H1 — transient-refresh operating premise

For a stable fast mode, (i) a tagged input contribution decays according to its configured decay timescale, while (ii) continuing bounded input refresh maintains a non-vanishing mode state, and (iii) stopping refresh returns the whole state to the same fast decay envelope.

### H0 — conventional leaky-mode explanation

The behaviour is fully explained by an ordinary linear SOE auxiliary state with the same decay rate and input. No distinct lepto-graph mechanism is needed for this experiment.

**Important:** H0 is expected to reproduce H1 if LG-01A is implemented exactly as specified. That is not an experimental defect. It is the required simplicity control. LG-01A cannot distinguish a lepto-mode from a conventional fast SOE channel; any additional claim must be earned in LG-01B or later.

## 3. Mathematical assumptions

### 3.1 State and mode bank

Use the repository's initial feature dimension and fixed four-rate SOE bank:

- feature dimension \(d=16\);
- four independent vector states \(z_\ell(t)\in\mathbb R^{16}\);
- fixed decay rates \(\gamma=(0.01,0.05,0.2,0.8)\) in the repository's normalized time units;
- \(\gamma=0.01\) is the slow-timescale reference;
- \(\gamma\in\{0.05,0.2,0.8\}\) are the declared fast-mode conditions.

The rates are inherited from the existing research configuration for comparability. They are not asserted to be optimal or universal. All rates, the 16-dimensional state, and the number of channels remain frozen for LG-01A confirmation.

For each channel:

\[
\frac{dz_\ell(t)}{dt}=-\gamma_\ell z_\ell(t)+u_\ell(t),
\qquad \gamma_\ell>0.
\]

No cross-mode coupling, learned parameter, graph edge, adaptive decay rate or nonlinear term is present in LG-01A. The input injection is the identity map. The mode states are independent given their inputs.

### 3.2 Tagged contribution and refresh contribution

By linearity, split the mode state into:

\[
z_\ell(t)=z_\ell^{\mathrm{tag}}(t)+z_\ell^{\mathrm{refresh}}(t).
\]

At \(t=0\), inject a unit-norm tagged pulse \(q\in\mathbb R^{16}\) into the tagged component. After the pulse, it receives no further input:

\[
z_\ell^{\mathrm{tag}}(t)=q\,e^{-\gamma_\ell t}.
\]

The refresh component receives the external information stream:

\[
\frac{dz_\ell^{\mathrm{refresh}}}{dt}
=-\gamma_\ell z_\ell^{\mathrm{refresh}}+u_\ell(t).
\]

The combined state is the sum of the two. The decomposition is retained in the runner as an instrumentation/control device; the model-facing total state is not allowed to read a separate “tag age” field.

### 3.3 Exact discrete update

Use a piecewise-constant input over a fixed step \(\Delta t=0.125\). Integrate the linear mode exactly over each step:

\[
a_\ell=e^{-\gamma_\ell\Delta t},\qquad
b_\ell=\frac{1-a_\ell}{\gamma_\ell},
\]

\[
z_{\ell,k+1}=a_\ell z_{\ell,k}+b_\ell u_{\ell,k}.
\]

This avoids Euler-step stability error and makes the decay envelope directly testable. Use float64. All generated input vectors are bounded and normalized as specified below.

### 3.4 Boundedness assumption

For \(\|u_\ell(t)\|\le U_{\max}\), the stable continuous-time system satisfies:

\[
\|z_\ell(t)\|
\le e^{-\gamma_\ell t}\|z_\ell(0)\|
+\frac{U_{\max}}{\gamma_\ell}(1-e^{-\gamma_\ell t}).
\]

The runner must check the corresponding bound for each arm using its declared \(U_{\max}\). Continuous refresh has \(U_{\max}=1\); the matched-energy burst arm has \(U_{\max}=2\).

### 3.5 What is not assumed

- A non-zero state is not, by itself, evidence that the mode has stored a particular past item.
- The mode's derivative is not assumed to identify a recipient or destination.
- No edge, adjacency, target graph, relation label or route supervision is supplied.
- No biological equivalence is assumed.
- No claim of improved task performance is made.

## 4. Experimental conditions

Use 30 paired deterministic seeds: 101–130. For each seed and mode rate, generate one fixed input stream and reuse it across the matched arms. Use NumPy Generator(PCG64(seed)) and record the NumPy version.

The refresh input is a sequence of unit-norm vectors in \(\mathbb R^{16}\), generated by normalising seeded standard-Gaussian vectors. Each vector is held constant over one \(\Delta t\) step. The tagged pulse \(q\) is a fixed unit basis vector so its exact decay is independently checkable.

For each mode, use:
- refresh pre-roll: \(8\tau_\ell\), where \(\tau_\ell=1/\gamma_\ell\);
- tagged-pulse observation: \(4\tau_\ell\);
- post-refresh washout: \(3\tau_\ell\).

The pre-roll establishes the refresh-only reference response before the tagged pulse is introduced. Continue the pre-registered stream during the observation period. At the end of \(4\tau_\ell\), stop refresh and measure the \(3\tau_\ell\) washout.

### Arm A — pulse-only / no-refresh control

Inject \(q\), set \(u=0\), and observe decay. This establishes the natural washout baseline. It also provides the denominator for the refresh-versus-decay activity ratio.

### Arm B — continuous bounded refresh

After the \(8\tau_\ell\) refresh-only pre-roll, inject \(q\) into the combined state and continue the bounded unit-norm input at every time step. In parallel, maintain a matched refresh-only shadow with the same stream but no tagged pulse. The shadow is an evaluator-side reference only.

### Arm C — intermittent refresh, matched total input energy

Use the same four-step blocks as the continuous stream. Deliver a \(2u_k\) input on the first step of each four-step block and zero input on the other three steps, using the corresponding continuous-stream vector for that active step. This gives the same total squared input norm per four-step block:

\[
(1^2+1^2+1^2+1^2)=2^2+0^2+0^2+0^2.
\]

The intermittent arm has the same total input energy but a different temporal delivery pattern. Use a separate matched intermittent refresh-only shadow.

### Arm D — conventional SOE null baseline

Run the standard linear SOE auxiliary-state equation with the same \(\gamma_\ell\), dimension, input, initial condition, integration step and precision. It must match the lepto-mode candidate's output to numerical tolerance. This arm is the null explanation, not a competitor expected to lose.

### Slow reference

The \(\gamma=0.01\) channel is reported alongside the fast modes to show the longer retention horizon under the same input construction. It is a timescale reference, not a claim that this channel is a complete model of the later slow-memory registration mechanism.

## 5. Controls and matching

| Control | What it isolates |
|---|---|
| Pulse-only, no refresh | Natural decay of an individual historical contribution |
| Refresh-only shadow | State activity caused by the refresh stream without the tagged pulse |
| Continuous refresh | Whether sustained bounded input maintains an active state |
| Intermittent, equal-energy refresh | Whether temporal continuity matters beyond total input energy |
| Slow \(\gamma=0.01\) reference | Contrast between fast and slower decay horizons |
| Conventional SOE null | Whether the observed dynamics require anything beyond an ordinary leaky SOE state |

Pair the same input stream and seed across arms. Do not compare unmatched random streams. Report the exact input energy and peak input norm for each arm. The continuous and intermittent arms are energy-matched over each four-step block, not amplitude-matched.

## 6. Measurements

For every seed and rate, record:

1. **Tagged decay error:** maximum relative deviation between simulated tagged state and \(q e^{-\gamma t}\).
2. **Tagged residual at \(3\tau\):** \(\|z^{tag}(3\tau)\|/\|q\|\); theory predicts \(e^{-3}\approx0.0498\).
3. **Refresh activity ratio:** RMS norm of the combined state over each evaluation window divided by RMS norm of the pulse-only state over the same window.
4. **Reference tracking ratio:** RMS norm of the combined state divided by the matched refresh-only shadow RMS norm.
5. **Refresh input-response fidelity:** error between the simulated change caused by a controlled one-step input perturbation and its exact exponential response.
6. **Post-stop washout ratio:** state norm at \(3\tau\) after refresh stops divided by the state norm at the stop time.
7. **Boundedness:** maximum state norm and whether the analytic bound is respected at every step.
8. **Numerical validity:** finite values, deterministic replay, expected array dimensions, and parameter/configuration hashes.

RMS means the square root of the mean squared Euclidean state norm over the stated window. Evaluation windows are fixed at \(\tau_\ell/4\) with stride \(\tau_\ell/8\), restricted to the final observation interval \([3\tau_\ell,4\tau_\ell]\). No timestep is treated as an independent experimental replicate.

## 7. Pre-registered acceptance criteria

LG-01A receives an **operational pass** only if all of the following hold.

### A. Mathematical / implementation checks

1. Tagged decay maximum relative error is at most \(10^{-8}\) in every seed/rate.
2. Tagged residual at \(3\tau_\ell\) is at most \(0.05+10^{-8}\).
3. For a one-step perturbation \(\delta u\), the exact later state difference is \(b_\ell a_\ell^m\delta u\) after \(m\) subsequent steps. The controlled input-perturbation response matches this discrete Green's-function response with relative error at most \(10^{-8}\).
4. All states remain finite and satisfy the analytic boundedness envelope (allowing only a \(10^{-10}\) relative numerical tolerance).
5. Conventional SOE and candidate lepto-mode traces agree within \(10^{-10}\) relative tolerance under identical conditions.

### B. Operational refresh checks

For each of the three fast rates \(\gamma\in\{0.05,0.2,0.8\}\):

1. In the continuous-refresh arm, at least 90% of the evaluation windows in at least 27 of 30 seeds must satisfy both:
   - refresh activity ratio \(\ge5\);
   - reference tracking ratio in \([0.8,1.2]\).
2. After refresh stops, the state norm after \(3\tau_\ell\) must be no more than \(0.05+10^{-8}\) of its stop-time norm for every seed.
3. The no-refresh pulse-only arm must show the corresponding decay, rather than remaining active.
4. The matched intermittent-refresh arm must be reported under the same metrics. It is diagnostic rather than a gate for the main continuous-refresh claim.

The slow reference is reported with the same metrics but does not determine the fast-mode pass/fail gate.

### C. Replication and reporting checks

- All 30 paired seeds and all four rates are present.
- Seed-level and aggregate metrics, input energies, state norms, and raw run metadata are included.
- Re-running the same code/configuration/seed reproduces the same result within the declared numerical tolerance.
- No held-out task outcome is used; LG-01A is a dynamical mechanism check, not a benchmark comparison.

## 8. Falsification and decision rules

### Valid result that contradicts H1

Provided all implementation/math checks pass, the declared operating premise is **not supported for this parameter range** if any fast rate fails the operational refresh criterion (fewer than 27/30 seeds pass). Do not proceed to LG-01B on the basis of a partial pass. A narrower rate range may be proposed only as a dated protocol revision with a fresh confirmation run, not by deleting a failed rate after inspection.

If the no-refresh control remains active after the predicted decay horizon, or the continuous-refresh arm is not materially more active than pulse-only, the claim that refresh is maintaining the operational state is not supported.

### Result that narrows, rather than falsifies, H1

If continuous and intermittent refresh have comparable activity under matched energy, the result does not negate refresh-dependent activity. It does weaken any claim that **uninterrupted** delivery is necessary; the wording should become ongoing/recurrent refresh unless later evidence establishes a continuity advantage.

### Result that does not establish novelty

If the conventional SOE null reproduces the candidate exactly, the LG-01A dynamics are conventional leaky-SOE dynamics. This is the expected null outcome and places a strict ceiling on the claim: LG-01A validates a useful operating premise, not a distinct lepto-graph primitive.

### Invalid or inconclusive runs

A run is **invalid**, not a scientific falsification, if it has a configuration/hash mismatch, missing seeds, non-finite values from an implementation defect, non-deterministic replay beyond tolerance, input leakage, or failed exact-update checks.

A run is **inconclusive** if it is valid but incomplete or underpowered relative to the frozen seed/window requirements. Do not proceed to LG-01B until the gate is resolved.

## 9. Prohibited additions in LG-01A

Do not add:
- graph edges, adjacency matrices or destination selection;
- route learning, relation labels or target topology;
- slow-memory trajectory registration beyond the fixed slow-rate reference;
- mode creation/deletion or adaptive decay;
- connection plasticity;
- nonlinear terms or learned input maps;
- Grassmannian state updates.

Any such addition changes the experiment and requires a new specification version.
